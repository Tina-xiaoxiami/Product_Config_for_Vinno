# 探头配置：子系列共同总集与发布

## 维护单位

复用型号管理、配置管理和白皮书的共享子系列及组合，不再依赖旧 `config_group`。
组合实时解析成员并按机型身份去重；共同总集有稳定编号，机型成员由数据库唯一约束保证只有一个权威总集。
重叠组合不能创建配置副本，页面会提示打开已有总集。可在已有总集中调整共享子系列范围。
共同总集的变更影响全部成员；机型特有差异按字段保存，编辑备注不冻结其他继承字段。

与型号停用功能一起部署时，共享定义仍完整保留停用成员，但新配置结果只计算启用机型。
停用成员的差异及总集归属会保留；重新启用并刷新范围后恢复原差异。
只有明确从共享范围移出的成员才移除当前草稿差异，已发布历史始终保留。

## 使用流程

1. 在「探头配置」选择已有总集，或选择子系列、已保存组合后新建总集。
2. 新建总集会汇总成员机型当前配置或定义配置为 X/O/Δ 的探头物料。已有总集可点击「补齐机型探头」增量追加；已有内容和机型差异保留，不会删除物料或直接发布。编辑共同探头/IPN/功能条目；在「机型结果与差异」选择具体机型维护特有限制、排除应用、优先级及说明。
3. 手工编辑应用后保存草稿；Excel先预览再保存草稿。两者都不会修改已发布数据。
4. 查看待发布变更，填写业务版本与发布说明，核对各机型结果后发布。
5. 总集不变但主配置有更新时，点击「建立下一版草稿」，再核对发布。
6. 「版本历史」查看完整快照、导出、比较，或把旧版恢复为新草稿；恢复不会覆盖已发布历史。

## 机型结果规则

- 所有机型共用探头/功能条目总集，实际结果由各机型主配置和探头特有差异共同决定。
- 定义值关联主配置 `final_config`，现状关联 `current_config`；选型类别原样展示在来源信息中。
- 主配置 X/O/Δ 表示具备对应配置，仍保留标配/选配标记。N/A 表示该机型不适用。
- 缺失配置、未定义、特殊标记、身份缺失或映射不唯一显示待确认；不把 # 推断为注册结论。
- 探头按明确变体/IPN映射，功能优先使用已有配置项身份；禁止模糊名称匹配。
- 非空应用排除使有效支持状态为条件支持；排除项超出类别应用范围时返回待确认。
- 类别模板不自动成为确认的机型支持结论。

## 草稿和发布实现

`probe_workspaces` 保存共同总集的一份已发布数据及一份隔离草稿，revision 用于并发编辑保护。
`probe_workspace_members` 防止同一机型重复归属；历史快照不会因成员调整而变化。
`probe_workspace_releases` 保存范围、共享定义修订号、完整规则、机型差异、目录身份、来源配置和计算结果。

发布复用主配置版本号预检、未提交草稿检查、共同快照构建器以及 `ConfigVersion` 存储。
同一总集跨父系列时，在一个数据库事务中为各父系列创建配置版本，并在探头发布批次记录它们的编号。
未填版本号时，分别按各父系列的已有版本递增。主配置仍有草稿时禁止探头发布，需先处理主配置草稿。
发布预览签名包含草稿修订、共享范围、业务版本、说明、身份目录和来源配置；变化后要求重新预览。
发布先获得数据库写锁，再重新校验和一次性提交，避免部分系列发布成功。
后续普通配置发布的共同快照构建器也包含适用的已发布探头规则与当次机型结果。

已发布探头查询和导出读取冻结结果；草稿结果读取当前工作配置，页面明确其为待发布预览。
因此主配置修改不会悄悄改写已经发布的探头版本。

## Excel

导出包含「范围及版本」「共同总集」「机型差异」「机型结果」「编号与名称对照」。
稳定编号用于匹配；可读名称/IPN为核对信息。共同总集及机型差异工作表按完整内容替换，不把省略行当作保留。
机型差异空单元格表示继承；`[]` 清空应用排除；优先级 `(清空)` 表示明确清除；说明 `""` 表示明确空说明。
未知编号、重复条目、差异越界、公式、损坏文件、过期修订和错误范围均阻止导入。
先查看差异预览，再保存草稿；导入和手工保存共用校验，预览、发布及导出共用结果计算。

## 现有数据与启动

启动时只新增三张工作区表，不自动改写旧探头数据、不生成历史发布版本。
建立总集后，原有机型配置、应用排除、优先级及说明进入带「历史数据待核对」标记的初始草稿。
共同定义按已提交类别模板填充，现状功能默认待确认，原机型差异保留，避免把探头可用性或多数值推断成已验证的功能支持。核对后首次发布才建立基线。

物料优先按唯一 IPN 对应到探头主数据；缺少主数据时用配置项的稳定来源身份保存在 JSON 目录和草稿中，不写入探头主表。来源编号用负的配置项 ID，始终可解析；后补主数据登记也不改旧行键或机型差异。分类只接受唯一 IPN 或一致的精确名称对应，冲突和未匹配分类保持待确认，页面显示清单供核对。每个机型仍通过其自己的主配置计算 N/A、缺失或支持范围。
旧直接修改配置、直接导入、伪回滚等写入接口返回409，提示使用新草稿入口；原始数据和旧只读接口保留。

## 验证

后端 API 集成测试使用临时数据库覆盖组合去重、差异、草稿、预览过期、原子发布、来源变化、历史、恢复及Excel。
前端 Node 测试覆盖共同值编辑、字段继承、成员刷新、关闭保护和目标范围。
Linux GitHub Actions 使用 Playwright 实际验证组合选择、编辑、保存、不同机型结果、发布、历史及导出。
浏览器夹具强制使用 `/tmp/probe-e2e*` 数据库，拒绝连接正式库。
异步 SQLAlchemy 测试覆盖率使用 `backend/coverage.ini` 同时追踪 thread/greenlet。
