# 统一发布工作区

以产品配置管理系统为统一入口，复用产品管理工作台的发布资料导入、版本历史、版本对比和证据检索。发布模块通过 FastAPI 挂载到 `/release-workbench`，与原有接口共用 8086 后端；Vite 3006 同时代理该路径。无需 5050 后端。

## 日常操作

1. 打开“功能发布 → 文件同步”，选择对应项目。
2. 新文件放到已登记的 Release Note 文件夹后，点“目录与扫描 → 扫描预览”，核对版本和文件，再导入。未变化的文件不会重复导入。
3. 在“发布资料检索”中检索关键词，选择产品、版本或版本系列，打开命中原文核对。
4. 在“发布版本”和“发布对比”中查看历史和差异；按 IPN 确认的发布记录仍在“功能版本管理”。

扫描有规则限制：读取版本目录内符合命名规则的最终 Word `.docx` Release Note，跳过 URM 与非最终稿。PDF/技术 Excel 等历史资料通过搜索页的“历史补充资料”登记，不会自动变成正式功能记录。“刷新”只更新页面当前数据，不会代替扫描目录。

## 保留与屏蔽

| 能力 | 统一位置 |
|---|---|
| 配置、机型、探头、功能/IPN身份、注册资料、已发布问答 | 原生配置系统页面 |
| Release Note 扫描与候选、发布历史、发布版本对比、带出处检索 | 功能发布工作区 |
| 旧工作台侧栏与重复主数据编辑 | 集成模式隐藏并限制写入 |

发布资料库与配置主库继续区分：资料中的提及是证据，不能自动覆盖正式配置或创建第二套 IPN 功能身份。已有历史候选与功能关联保留，但新增正式身份应使用原生“基础数据管理 → 功能管理”。原文文件保持只读。

## 本机配置与维护

发布模块的 Python 实现以固定 Git 版本内置，来源与差异见 `backend/tracker/VENDOR.md`。本机路径及数据库不进入 Git。整合部署应引用原发布库并保留原有只读根目录，不创建第二份日常工作库；重新启动前用 SQLite 在线备份保存数据库。

现有安装导入路径配置（在 `backend` 目录运行；不会复制或搬动数据库）：

```bash
python3 -m scripts.import_release_workbench_config "/旧产品管理工作台项目绝对路径"
```

生成 `backend/config/release_workbench.local.json`（Git 忽略），保存解析后的绝对路径。已有文件默认拒绝覆盖。可用 `RELEASE_WORKBENCH_CONFIG` 指定其他配置，或 `RELEASE_WORKBENCH_DATABASE` 指定发布库；配置主库始终取当前服务的 `DATABASE_URL`，不会使用旧配置里的主库路径。全新安装参考 `backend/config/release_workbench.example.json` 设置只读资料根。

旧工作台快捷方式在原项目的 `config/unified-system.path` 写入统一系统项目目录后，会调用这里的服务管理器，打开 `/release`。路径不存在会报错，不再静默启动旧页面。

启动、停止及日志仍使用 `start.command` / `stop.command` 和 `.runtime/`。修改后端代码或本机配置后需要停止并重新启动；仅刷新浏览器不会重载后台代码。

不要同时运行旧 5050 工作台维护同一发布库。备用旧代码保留用于追溯；日常只从统一入口操作。集成不合并两边的业务表、不批量确认待审核材料，也不自动发布知识库答案。
