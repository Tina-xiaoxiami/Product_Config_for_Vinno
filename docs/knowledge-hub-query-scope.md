# KH-02 查询范围隔离

日期：2026-11-02。范围：查询范围隔离及18条答案确认材料准备。实现位于现有产品知识库，不新增功能专属页面。正式业务库本轮只读演练，尚未执行迁移或部署；18条答案未更改、未重新发布，也未自动赋予范围。

## 查询与历史维护

公开提问须明确国家代码、国内/海外市场、完整机型ID及软件版本。缺任一条件返回 `needs_clarification`，不创建问题、不计询问次数、不返回历史正式答案。国家和市场冲突、机型与所属市场冲突、无效机型或通配软件版本会被拒绝。

范围由服务端规范化：国家大写，数字软件版本按段规范化，机型ID附带当前完整名称及正式系列名称。`scope_key`为规范化范围的确定性JSON，参与问题和别名的复合唯一约束。国内/海外、国家、机型或软件版本不同的同一问法形成独立记录，不能共享别名、计数、相似答案或合并关系。

存量问答保留空范围，不从问题文字、当前配置或最大版本号推断。维护列表不带范围时仅列这些历史记录；详情、答案、引文和修订历史保留。完整范围的查询不会回退到它们。旧库尚未迁移时，维护读取仍可使用；指定范围提问返回明确的迁移提示。历史范围未核实的答案不能直接在此增量中重新发布。

界面顶部提供紧凑的市场、国家、完整机型和软件版本控件，默认均不代填。队列分“当前查询范围”和“历史范围待核实”。修改范围立即清除旧结果；请求序号、范围指纹和编辑会话标识防止迟到的查询、列表、候选或保存结果污染当前范围或新编辑器。

```json
{
  "question": "这个功能如何操作？",
  "scope": {
    "country": "CN",
    "market": "domestic",
    "product_model_id": 123,
    "software_version": "1.14.80"
  }
}
```

示例机型ID仅为占位，应从当前机型目录选择。范围属于问题身份，答案编辑不能通过额外参数悄悄改变它。

## 材料候选及引用边界

已有资料缺少完整的“文档→机型→软件适用范围”关系。本次仅接受国家、市场、完整机型名称及软件版本均有明确元数据的匹配；同市场同名机型无法唯一定位时，候选不展示、手工引用也拒绝。

“V10”系列标签不能直接证明某完整机型适用；说明书的 `R10` 是资料修订，不能解释为软件版本。缺少明确范围的资料继续保留在资料中心和维护检索中，但不充作当前范围的答案依据。这意味着新范围候选可能更少，不能将其解释为产品不支持或无相关资料。下一阶段应复用受控范围登记和文档发布契约补齐关系。

正式答案仍由负责人明确发布，不能从候选片段自动升级。没有文档引文的历史记录也不等于答案错误。

## 迁移与兼容

旧问题和别名的规范化文本均为全局唯一。迁移重建这两张表，改为 `(scope_key, normalized_question)`、`(scope_key, normalized_phrasing)`，并以问题ID及范围建立别名复合外键。

```sh
# 默认只读演练，必须显式提供数据库。
python3 backend/scripts/migrate_knowledge_scopes.py --database /path/to/product_config.db

# 部署时停止旧知识库服务，确认备份及演练结果后执行。
python3 backend/scripts/migrate_knowledge_scopes.py --database /path/to/product_config.db --apply
```

迁移不在应用启动时自动执行。`--apply`先取得写锁、在线备份，再在同一事务中重建，核对原列内容、ID、所有相关子表、外键、显式索引/触发器及序列高水位。存量范围均为空。未知结构、半迁移或核验失败会阻断或回滚，不部分生效。

部署必须同时切换匹配的服务代码与结构，不能让旧知识库写入程序继续连接已启用范围的新库。发布工作库与受控原件不需要迁移。回退前先停止写入并备份当前库；若恢复迁移前备份，须评估迁移后的新记录，不能直接删列或强退旧代码。

问答快照在有明确范围时使用v2；纯历史内容继续保持v1输出兼容。v1恢复为历史空范围；v2恢复前核对目标机型ID、完整名称及系列，拒绝同号异机型。最终内容复核在恢复事务提交前进行，失败整体回滚。批量种子整理默认仅处理历史范围，不用其他范围的正式答案覆盖种子。
