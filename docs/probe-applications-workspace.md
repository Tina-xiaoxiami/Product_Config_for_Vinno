# 探头&应用合并工作区

2026-11-03。模板管理之外，探头型号和应用范围统一进入“探头&应用”，使用同一个探头类别选择器。合并界面不合并或迁移底层数据，也不重新实现应用提交或探头变体导入流程。

## 页面与入口

左侧选择探头类别，右侧同时查看该类别的常规/POC应用和探头型号、内部型号/IPN。应用区紧凑显示，型号表使用既有共用表格的列设置、筛选、宽度记忆及容器滚动。内部型号、IPN及历史记录始终按同一物料分组，不分别去重造成错配。

唯一页面路径沿用 `/probe-models`，原 `/applications?category_id=3` 归一到同页并保留类别参数、定位应用区。型号行的“类别应用”定位本页应用区，不再跳到另一个管理页面。顶部仅保留模板管理、探头&应用两个标签。

应用区继续复用原 `ApplicationsView` 的应用定义、类别关联、单次批量提交和版本操作，作为受控嵌入区接收父页面的类别。型号、变体、类别维护及原Excel导入导出保留，由原探头控制器处理。没有新增后端接口、存储表或应用关联副本。

## 编辑与刷新

- 常规、POC应用仍按探头类别维护，不恢复已经废弃的型号级应用写入。
- 应用编辑按类别保留待提交修改，切换类别不会重建子区或清空草稿。按类别和请求序号隔离迟响应，不能把上一类别的应用显示到当前类别。
- 提交中禁止切换或删除类别；有未处理应用编辑时，父页面的刷新、删除和离开动作须先处理编辑状态。浏览器关闭保留未保存提醒，避免合并后绕过原编辑约束。
- 应用提交或回滚成功后更新型号区的应用计数；刷新只读信息不会递归触发业务提交。
