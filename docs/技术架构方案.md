# 产品配置管理系统技术架构方案

## 1. 系统架构概述

本系统采用前后端分离架构，后端提供RESTful API服务，前端通过HTTP调用后端接口。

```
┌─────────────────┐     HTTP/REST     ┌─────────────────┐
│   Vue 3 前端    │ ──────────────── │  FastAPI 后端   │
│   (Port 3006)   │                   │   (Port 8086)   │
└─────────────────┘                   └─────────────────┘
                                              │
                                              ▼
                                      ┌─────────────────┐
                                      │    SQLite DB    │
                                      │ product_config  │
                                      └─────────────────┘
```

## 2. 技术栈选型

### 2.1 后端技术栈

| 技术 | 版本 | 说明 |
|-----|------|------|
| Python | 3.10+ | 主语言 |
| FastAPI | 0.100+ | 高性能异步Web框架 |
| SQLAlchemy | 2.0+ | ORM框架（异步模式） |
| SQLite | 3 | 嵌入式数据库 |
| openpyxl | 3.1+ | Excel文件处理 |
| Pydantic | 2.0+ | 数据验证 |
| uvicorn | 0.23+ | ASGI服务器 |

**选型理由：**
- FastAPI：异步支持、自动API文档、高性能
- SQLAlchemy 2.0：异步ORM、成熟稳定
- SQLite：轻量级、零配置、适合中小规模数据
- openpyxl：Excel合并单元格解析能力强

### 2.2 前端技术栈

| 技术 | 版本 | 说明 |
|-----|------|------|
| Vue | 3.3+ | 前端框架 |
| Element Plus | 2.4+ | UI组件库 |
| Vite | 4.4+ | 构建工具 |
| Axios | 1.5+ | HTTP客户端 |
| Vue Router | 4.2+ | 路由管理 |

**选型理由：**
- Vue 3：Composition API、响应式系统优化
- Element Plus：表格组件强大、开箱即用
- Vite：快速开发体验、HMR热更新

## 6. Excel处理方案

### 6.1 导入流程

```
上传文件 → 解析合并单元格 → 提取型号列表 → 提取配置项 → 预览确认 → 写入数据库
```

### 6.2 合并单元格解析算法

1. 读取Excel文件的合并单元格信息（merged_cells）
2. 第一行合并单元格识别为产品型号
3. 第二行合并单元格识别为配置状态类型（当前配置、最终配置、选型配置、研发状态）
4. 后续行解析配置项数据，按列对应型号和状态类型

### 6.3 导出格式

保持导入时的合并单元格结构：
- 第一行：型号名称（合并）
- 第二行：状态类型（合并）
- 数据行：配置数据

## 7. 版本管理机制

### 7.1 版本快照结构

```json
{
  "models": [{"id": 1, "name": "型号A"}, ...],
  "items": [
    {
      "id": 1,
      "row_index": 1,
      "rd_name": "研发名称",
      "ipn": "IPN001",
      "values": {
        "1": {"current_config": "值", "final_config": "值", ...},
        "2": {"current_config": "值", ...}
      }
    },
    ...
  ]
}
```

### 7.2 版本对比算法

1. 解析两个版本的JSON快照
2. 构建(row_index, ipn)索引
3. 对比索引找出新增、删除项
4. 对公共项的values逐字段对比
5. 忽略空值和"N/A"的差异

### 7.3 回滚机制

回滚不直接修改历史版本，而是：
1. 从目标版本快照恢复数据
2. 创建新版本记录
3. 新版本标注"回滚自XXX版本"

## 9. 性能优化

### 9.1 后端优化
- 异步数据库操作（AsyncSession）
- 分页查询（避免全量加载）
- JSON快照压缩存储

### 9.2 前端优化
- 表格虚拟滚动（大量数据时）
- 分页加载配置数据
- 缓存枚举值下拉选项

## 10. 安全考虑

### 10.1 数据安全
- 版本快照不可修改（只读）
- 回滚创建新版本而非覆盖
- 外键约束确保数据完整性

### 10.2 输入验证
- Pydantic验证请求参数
- Excel文件类型校验
- 文件大小限制

## 11. 部署方案

### 11.1 开发环境
```bash
# 后端
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8086

# 前端
cd frontend
npm install
npm run dev -- --port 3006
```

### 11.2 生产部署建议
- 后端：使用Gunicorn + Uvicorn workers
- 前端：构建静态文件，使用Nginx托管
- 数据库：可升级为PostgreSQL/MySQL
