# 知识库统一功能主数据方案

状态：已确认，数据库副本迁移验证完成

确认日期：2026-09-01

## 1. 唯一身份

- IPN 是功能的业务唯一标识；
- 数据库内部保留整数 `id` 作为技术主键，现有外键继续引用 `id`；
- `features.ipn` 最终必须非空并建立规范化唯一约束；
- IPN 使用文本类型保存，规范化时只去除首尾空格并统一字母大小写，不删除前导零；
- 相同名称但IPN不同的记录不得自动合并。

## 2. 主名称和备用名

- `config_items.zh_desc` 是默认主中文名；
- `config_items.en_desc` 是默认主英文名；
- `config_items.rd_name`、现有 `features.name`、Release Note、白皮书、说明书及人工确认名称作为备用名候选；
- 同一IPN允许一个当前主中文名、一个当前主英文名和多个中英文备用名；
- 主名称变更时保留旧名称、来源、有效期和审核记录，不覆盖历史。

## 3. 不作为普通备用名的关系

以下内容默认建立功能关系，不能仅因名称相似而自动合并为备用名；经产品负责人明确确认为同一功能时，可记录确认来源后归并：

- 父功能、子功能；
- 功能参数；
- 组合功能；
- 后继或替代功能；
- 相同名称但不同IPN的功能。

例如 `6000034 / 穿刺增强 / Needle enhancement` 是标准功能；“针增益调节”是参数，`6000301 / 自动穿刺增强` 是另一个功能身份。“穿刺引导&穿刺增强”已于2026-09-01经用户确认归并到 `6000034`，作为备用名保留。

## 5. 迁移安全门槛

1. 所有迁移先在数据库副本执行；
2. 迁移前后核对39条功能、探头配置关系和版本快照数量；
3. 26条唯一匹配可以自动预填，但仍保留来源记录；
4. 13条待确认项逐项确认IPN或功能关系；
5. 任一IPN重复、缺失或外键数量变化时整体回滚；
6. 正式库迁移前生成备份、差异报告和回滚方案；
7. 原始配置、Release Note和文档记录不删除，只改为标准功能的证据来源。
