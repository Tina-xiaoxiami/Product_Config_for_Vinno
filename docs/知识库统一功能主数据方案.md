# 知识库统一功能主数据方案

状态：已上线到产品配置管理系统

确认日期：2026-09-01

## 1. 唯一身份

- IPN 是功能的业务唯一标识；
- 数据库内部保留整数 `id` 作为技术主键，现有外键继续引用 `id`；
- 单一IPN功能的 `features.ipn` 必须非空并建立规范化唯一约束；
- 一个旧功能名对应多个IPN时，`features.ipn` 保持为空，通过 `feature_config_item_links` 分别关联，不强行选择一个IPN；
- IPN 使用文本类型保存，规范化时只去除首尾空格并统一字母大小写，不删除前导零；
- 相同名称但IPN不同的记录不得自动合并。

## 2. 主名称和备用名

- `config_items.zh_desc` 是默认主中文名；
- `config_items.en_desc` 是默认主英文名；
- `config_items.rd_name` 是研发内部识别字段，只用于迁移匹配和内部检索，不作为可展示的主名或备用名；尾部 `【启用】`、`【禁用】`、`【停用】`属于状态并从名称识别中剥离；
- 现有 `features.name`、Release Note、白皮书、说明书及人工确认名称作为曾用名候选；
- 同一IPN允许一个当前主中文名、一个当前主英文名和多个中英文备用名；
- 主名称变更时保留旧名称、来源、有效期和审核记录，不覆盖历史。
- 中文、英文曾用名分别记录语言，但查询不按材料语言限制；中文材料中出现英文名同样能够命中功能。

## 3. 不作为普通备用名的关系

以下内容默认建立功能关系，不能仅因名称相似而自动合并为备用名；经产品负责人明确确认为同一功能时，可记录确认来源后归并：

- 父功能、子功能；
- 功能参数；
- 组合功能；
- 后继或替代功能；
- 相同名称但不同IPN的功能。

例如 `6000034 / 穿刺增强 / Needle enhancement` 是标准功能；“针增益调节”是参数，`6000301 / 自动穿刺增强` 是另一个功能身份。“穿刺引导&穿刺增强”已于2026-09-01经用户确认归并到 `6000034`，作为备用名保留。

## 10. 系统使用

- 启动系统后访问 `http://localhost:3006/knowledge`，或点击左侧“产品知识库”；
- 功能主数据统一在“基础数据管理 > 功能管理”维护，国内注册数据统一在“基础数据管理 > 注册管理”查看；知识库不再维护第二份功能、探头或注册主数据，只做只读聚合查询；
- 功能管理中的一次保存会在同一事务内更新功能分组、排序、中英文主名、中英文曾用名和 IPN 关系，任一项校验失败时整次保存回滚；
- 名称核对有两个基准：功能名称标准表和配置管理里的中文描述/英文描述（按 IPN 关联），两者分别提示；白皮书正文中的功能写法（英文缩写 + 中文说法）也按这两个基准逐条核对，列出正文出处，括号补充与（可选）(选配) 标记不参与比对；
- 功能中英文名称的标准定义来自完整功能名称表（中文名称/英文名称/中文UI），在“功能管理 > 标准名称”中整表导入；系统将标准定义与功能主数据比对，按一致、写法不同、不一致、标准表有但系统未登记、系统有但标准表未收录分类提示，并在所有显示功能名称的位置（功能管理、产品知识库、模板管理、探头配置）标注提示，只提示不改写正式数据；
- 需要批量更新时，功能管理提供“导出模板 / 导入更新”：模板包含当前功能主数据、填写说明和 IPN 对照表，上传后先预览逐行的新增、更新、无变化和校验错误，确认后才写入。导入按功能ID → 主IPN → 功能组+中文主名称匹配，可新建功能和功能组；文件中未出现的功能不删除、不停用，主IPN 已属于其它功能或 IPN 无法唯一匹配时整份文件回滚，主名称或 IPN 关系变化的功能才标记为已确认身份；
- 注册管理保留注册材料中的原始探头型号，并通过 IPN 显示“探头管理”中的基础探头型号；注册红线继续通过受控差异表导入，不开放无来源的手工改写；
- 注册管理默认按原始差异表样式展示“三个型号一组”的型号/差异两行表，只突出不适用或未注册探头；完整型号×探头矩阵保留在“逐型号明细”页签，注册资料版本默认收起；
- “功能主数据”可按 IPN、中英文主名、中文曾用名、英文曾用名和研发内部识别名搜索，并可按自动匹配、人工确认、关系型功能筛选；研发内部识别名只参与检索，不在备用名区域展示；
- “国内注册与策略”可选择完整产品型号，按探头型号、IPN、注册状态和最终判定查询；
- 页面分栏展示“注册状态”“选型类别（正式）”“当前配置（辅助）”和“最终判定”：未注册只取注册差异表，已注册探头优先取正式选型类别，缺少正式选型时才展示研发当前配置作为辅助；
- `VINNO 9_Private` 和 `VINNO 9 综合版` 均以 `VINNO 9` 为注册基础型号，但产品策略仍读取各自完整产品型号；
- 产品机型与注册证、注册基础型号建立显式映射；注册查询固定沿“产品机型 → 注册证 → 当前有效资料版本 → 注册基础型号/探头”读取，不检索其他注册证的数据。产品型号页面展示注册证号和对应注册基础型号；
- 国内注册资料按注册证独立建立版本内快照。注册证 PDF 与差异表 Excel 成对提交，自动解析国家—型号—探头关系，确认产品机型映射后原子发布；同一国家允许多张注册证同时生效，同一产品如对应多张注册证，查询结果按注册证分别展示，不合并红线；
- 产品完整型号与注册基础型号使用注册包专用映射，不复用会影响产品配置继承的 `config_group`。同一注册证建立下一版本时，已批准映射自动沿用并保持批准状态，新推断映射继续等待确认；
- “注册差异表原文”使用受控文档 ID 打开登记的 Excel 原文件；
- “原始资料”可按资料名、版本、产品和资料类型检索；
- PDF 和图片使用受控文档 ID 在页面内预览；Word、Excel 等 Office 文件保留“打开原文”；
- 后端只接受数据库中已登记的文档 ID，不接受用户传入任意文件路径。

判定顺序固定如下：

1. 注册差异表标记为不支持时，最终判定为 `# 未注册`，即使研发当前配置为 `X` 也不得覆盖；
2. 已注册且“选型类别”存在 `X/O/Δ` 时，以选型类别作为正式产品策略；
3. 已注册但选型类别缺失时，`current_config` 的 `X/O/Δ` 仅作为研发辅助信息；
4. `current_config` 中的 `#` 不用于推导未注册，未注册只认注册差异表；
5. 注册表存在但配置系统尚无对应 IPN 的探头继续保留，策略显示“未定义”，不丢弃注册记录。

## 12. 后续阶段

当前完成的是“统一功能主数据 + 原始资料库 + 国内注册/策略分层查询 + 成对注册资料版本 + 确认式问答闭环 + 受控正文抽取”。问答闭环包括：直接提问、已发布答案复用、未知问题回流、相似/曾用问法、原文依据、答案版本和变更记录。相似匹配不会跨产品型号、国内/海外范围或正反意图给出结论。

注册证与注册差异表按国家和注册单元组成不可拆分的注册资料包，并以注册证号确认身份。每个版本固定保存两份资料的 ID、版本、SHA-256、Obsidian 受控原件路径及差异表生成的结构化快照；组合哈希保证重复登记不会新增版本。两份资料始终成对保存，但允许其中一份沿用上一版，例如仅注册证换版时可复用同一差异表批次。更新时先形成草稿，保留当前版，并自动记录文件、型号、通道数、探头、探头 IPN 和型号-探头注册状态变化；发布后才原子切换当前版本。已批准的完整产品型号映射会自动带入同一注册证的下一版本，新推断映射仍需确认。

受控正文抽取按资料格式保留来源位置：PDF记录页码，DOCX记录标题/段落/表格位置，XLSX记录工作表和行号。检索到的材料片段仅作为候选依据，可以带入答案草稿，但不会绕过人工确认直接发布。

后续按原需求增加：

1. 下游账号与查询权限（当前按要求暂缓）；
2. 海外按国家-基础型号-探头型号登记，配置数据以 `oversea` 为准；
3. 根据实际问答命中情况继续优化候选片段排序和同义词词典。
4. 收到新的国内注册证及配套差异依据后，继续按独立注册证资料包导入，不合并不同注册单元。
