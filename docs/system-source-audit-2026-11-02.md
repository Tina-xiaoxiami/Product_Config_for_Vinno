# 系统数据源与重复机制检查（2026-11-02）

本次按当前生产入口追踪主数据、写入、查询和历史回放链路，检查的是实际读写机制及现场数据，而不是根据页面名称判断是否重复。正式库只读检查；数据问题的复现和写入测试均使用临时库。

## 已复现的问题

- 旧型号应用表在现场没有记录，而类别应用已有 138 条关联，旧页面因此显示所有应用数为 0。
- 多个页面被 KeepAlive 保留，却只在首次挂载取数，导致跨模块修改后返回仍显示旧目录。共用刷新工具覆盖首次挂载、正常返回和延迟挂载子页面，并尊重未保存编辑。
- 主库与发布系统对 86 个文件分别登记；5 份新 Release Note 的 69 段正文未进入发布搜索。另 3 个文件在旧登记中产生 13 条冗余索引来源。
- 主库归档不影响旧发布候选；旧扫描导入遇到原件变更还会重新激活归档记录。
- 两个窗口并发维护时可能产生重名机型或重复类别应用关系。现已将校验和写入放到同一数据库写事务中。
- 配置导入预览只回滚 SAVEPOINT 时，自建的外层事务仍可持有写锁；现区分自建与调用者事务，既释放自建锁，也保留调用者未提交内容。

## 保留的历史及待核对数据

不删除旧功能、机型、应用关系、资料版本、审核及证据记录。搜索去重不是删除资料历史，当前名称投影也不改写历史原文。

现场有 **38 条模板排除规则**包含“早”“中”等无法直接匹配当前应用表的名称，三个工作区草稿也继承了部分旧名称。现有规则可以展开“早\\中\\晚孕”，但不能据此证明已拆碎的单字必然指向哪个应用。本次不猜测改写这些记录；显示层明确标出旧排除名称，编辑时提醒按当前应用核对，新工作区的待确认保护继续保留。

2026-11-04 已按原始模板逐格补核：30 条已有明确证据并完成规范，3 份未发布总集中 715 处继承值同步修正；剩余双平面 8 条为原件应用范围与功能限制矛盾，保留原值并逐条列出单元格。见 [逐项核对与处理结果](probe-exclusion-reconciliation-2026-11-04.md)。

旧探头配置表和其历史导出仍代表旧配置记录；当前子系列编辑、计算、发布使用工作区及发布快照。历史读取保留其历史含义，不通过复制当前草稿来伪装同步。注册版本和海外国家资料也继续保留各自证据范围。

探头列表还发现同一物料重复显示。现复用配置矩阵的探头/IPN/内部型号/备注组合规则合并标签，显示关联历史数量；不同备注或缺少可识别物料字段的记录不合并，变体维护仍可访问原始历史记录。

## 验证约定

新增回归涵盖两侧应用列表即时一致、原子提交和失败回滚、旧写入口无副作用、并发创建/改名/导入、别名保留、预览锁释放及调用者事务保护、系列分页、缓存返回、真实 Vue KeepAlive 生命周期，以及资料归档、新资料入索引、搜索去重和旧预览引用。

本地验收只通过页面读取和索引刷新检查，不执行正式配置发布、注册状态变更、资料归档或模板规则批量改写。

最终验证：后端全量 **1,080 项通过**；实际预览检查后补充的页码、目录和截断边界相关 **63 项回归通过**。前端全量 **625 项通过**，生产构建通过；Python 与 Vue/JavaScript 专项审核发现的事务、并发和懒挂载刷新问题均已修复并复核。

Safari 实际检查型号应用数量、类别应用跳转、常规/POC 两侧数据，以及重复变体标签的合并显示；发布检索 API 已能找到新增的 `1.14.65` 原文，缺失的 89–93 号资料均完成索引。受控文件覆盖为 125 个物理来源，索引历史别名不计作重复物理文件。重启前后两个业务数据库逐表逐行与在线备份比较一致，完整性检查通过。

实际 PDF 原文预览发现旧逻辑把“无法提取完整编号章节”误作“指定页码不存在”。现复用同一原始 PDF 解析和快照校验，分别判断页码命中与章节完整性；合法命中页可预览，完整章节无法核实时仍保留提示，目录歧义、非法页及过期源继续拒绝定位。页码校验不受匹配列表分页/截断影响。
