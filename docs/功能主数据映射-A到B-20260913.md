## 二、主对照表（A 的 42 条 → B）

**「建议关系」取值**（对齐 B 的 `feature_relations.relation_type` 已有枚举
`parent/child/parameter/bundle/supersedes/equivalent`）：

| 本表取值 | 含义 | 落地到 B 的动作 |
|---------|------|----------------|
| `same` | 同一功能身份，IPN 一致 | A 名称登记为 B 的曾用名（`feature_names`, `name_type=alias`） |
| `related` | 相关功能，非同一身份 | 建 `feature_relations`（`bundle` 或 `child`），**不合并 IPN** |
| `version_variant` | 同一功能的版本变体，IPN 不同 | 建 `feature_relations`（`supersedes`），**两个 IPN 都保留** |
| `new` | B 无对应身份，需新建 | 阶段 1 建 `features` 行（多数可直接复用已存在的 config_item IPN） |

**置信度**：`确认` = 名称+代号+IPN 三方一致，无需人工复核；
`高` = 名称完全包含且代号一致，只需确认；
`中` = 名称部分一致或存在口径差异，需确认；
`低` = 证据不足，不可自动建立关系。
